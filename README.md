# بنك أسئلة المعلم

منصة ويب عربية تساعد كل معلم على بناء بنك أسئلة خاص به، مصنّف حسب المادة والصف والوحدة والصعوبة، ثم توليد اختبارات عشوائية متوازنة وعرضها وطباعتها مع نموذج إجابة.

## أهم المزايا

- حساب مستقل لكل معلم عبر Supabase Auth.
- عزل كامل للبيانات على مستوى قاعدة البيانات باستخدام Row Level Security.
- مواد بصفوف ومستويات، وأسئلة بأنواع: اختيار من متعدد، صح/خطأ، إجابة قصيرة.
- فلترة الأسئلة حسب المادة والصعوبة والنوع والوحدة، مع بحث نصي.
- توليد اختبار عشوائي بأعداد محددة من كل مستوى صعوبة، مع معاينة قبل الحفظ.
- خلط خيارات أسئلة الاختيار من متعدد مرة واحدة، وثبات الترتيب بعد الحفظ.
- استبدال أي سؤال في المعاينة بسؤال عشوائي آخر من نفس المادة.
- حفظ نسخة تاريخية كاملة (`snapshot`) لكل سؤال داخل الاختبار.
- عرض الاختبار المحفوظ وطباعته على A4، مع نموذج إجابة منفصل للطباعة.
- واجهة عربية RTL متجاوبة، دون أي build step، جاهزة لـ GitHub Pages.

## 1) وصف المشروع

«بنك أسئلة المعلم» مساحة عمل شخصية للمعلم:

1. ينشئ حساباً ويسجل الدخول.
2. يضيف مواده ويحدد الصف أو المستوى.
3. يضيف أسئلته ويصنفها حسب النوع والصعوبة والوحدة والدرجة.
4. يختار مادة وأعداداً من الأسئلة السهلة والمتوسطة والصعبة، فيولّد النظام اختباراً عشوائياً.
5. يراجع المعاينة، يستبدل ما يريد، ثم يحفظ الاختبار.
6. يفتح الاختبار لاحقاً ويطبعه، أو يطبع نموذج الإجابة.

لا يستطيع أي معلم رؤية أو تعديل أو حذف بيانات معلم آخر، حتى لو حاول تنفيذ استعلامات Supabase يدوياً؛ لأن الحماية مطبقة داخل PostgreSQL عبر RLS وليست في JavaScript فقط.

## 2) خطوات إعداد Supabase

### أ. إنشاء المشروع

1. ادخل إلى <https://supabase.com> وأنشئ مشروعاً جديداً.
2. انتظر حتى يكتمل تجهيز قاعدة البيانات.

### ب. تشغيل مخطط قاعدة البيانات

1. من لوحة المشروع افتح **SQL Editor**.
2. اضغط **New query**.
3. انسخ كامل محتوى الملف `supabase/schema.sql` والصقه ثم اضغط **Run**.

ينشئ الملف:

- الجداول: `subjects`, `questions`, `exams`, `exam_questions`.
- القيود والمفاتيح الأجنبية والفهارس.
- Trigger-ان: للتحقق من قواعد تخزين الأسئلة، وحماية `snapshot` داخل `exam_questions` من التعديل بعد الحفظ.
- 16 سياسة RLS (أربع لكل جدول) بصلاحية `TO authenticated`.
- الصلاحيات الأساسية للجداول.

### ج. الحصول على مفاتيح المشروع

1. افتح **Project Settings > API**.
2. انسخ:
   - **Project URL**
   - **anon public key**
3. افتح `js/config.js` واستبدل القيمتين:

```js
export const SUPABASE_URL = 'https://YOUR-PROJECT-REF.supabase.co';
export const SUPABASE_ANON_KEY = 'YOUR_SUPABASE_ANON_PUBLIC_KEY';
```

بعد الاستبدال يجب أن يبقى الملف هكذا:

```js
export const SUPABASE_URL = 'https://abcdefghijklmnop.supabase.co';
export const SUPABASE_ANON_KEY = 'eyJhbGciOi...';
```

> `SUPABASE_ANON_KEY` مفتاح عام مخصص لتطبيقات الواجهة، وليس سراً. لا تضع أبداً `service_role key` داخل المشروع.

## 3) إعداد Authentication

من لوحة Supabase افتح **Authentication > URL Configuration**.

### Site URL

ضع رابط الموقع الأساسي. عند النشر على GitHub Pages يكون مثلاً:

```text
https://username.github.io/repo-name/
```

### Redirect URLs

أضف الروابط التي يُسمح لـ Supabase بالعودة إليها بعد تأكيد البريد أو تسجيل الدخول:

```text
https://username.github.io/repo-name/**
http://localhost:8000/**
http://127.0.0.1:8000/**
```

> استبدل `username` و`repo-name` بقيمك الحقيقية. عند استخدام نطاق مخصص أضف رابطه أيضاً.

### كيف يعمل رابط العودة؟

داخل `js/auth.js` تُحسب قيمة `emailRedirectTo` من رابط الصفحة الحالي:

```js
new URL('./index.html', window.location.href)
```

لذلك يعمل محلياً وعلى GitHub Pages داخل مسار فرعي، دون كتابة رابط مستودع ثابت داخل كود المصادقة. لكن يجب أن يكون الناتج مطابقاً لأحد **Redirect URLs** المسموح بها في Supabase.

### تأكيد البريد الإلكتروني

- إذا كان **Confirm email** مفعّلاً: بعد إنشاء الحساب تظهر الرسالة:
  «تم إنشاء الحساب، تحقق من بريدك الإلكتروني لإكمال التسجيل.»
- إذا كان معطلاً: يسجّل المستخدم دخوله مباشرة بعد إنشاء الحساب.

يمكنك التحكم بذلك من **Authentication > Providers > Email**.

## 4) تشغيل المشروع محلياً

لا تستخدم فتح الملف مباشرة عبر `file://`؛ لأن وحدات ES Modules تحتاج خادماً.

من داخل مجلد المشروع شغّل أحد الأوامر:

```bash
python -m http.server 8000
```

أو:

```bash
npx serve .
```

ثم افتح:

```text
http://localhost:8000/
```

وتأكد من إضافة `http://localhost:8000/**` إلى Redirect URLs.

## 5) النشر على GitHub Pages

1. أنشئ مستودعاً جديداً على GitHub.
2. ارفع جميع ملفات المشروع إلى الفرع `main` مع الحفاظ على البنية.
3. من المستودع افتح **Settings > Pages**.
4. في **Build and deployment**:
   - Source: **Deploy from a branch**
   - Branch: **main**
   - Folder: **/(root)**
5. اضغط **Save** وانتظر نشر الموقع.
6. سيكون الرابط بالشكل:

```text
https://username.github.io/repo-name/
```

7. عدّل **Site URL** و**Redirect URLs** في Supabase ليطابقا الرابط الجديد.

كل المسارات داخل المشروع نسبية (`./...`)، لذلك يعمل الموقع من مسار فرعي مثل `username.github.io/repo-name/`.

## 6) اختبار عزل البيانات RLS

استخدم متصفحين مختلفين، أو نافذة عادية ونافذة تصفح متخفي، لتجنب اختلاط الجلسات.

### أ. حساب المعلم أ

1. أنشئ حساباً جديداً باسم «المعلم أ».
2. أضف مادة، مثلاً «الرياضيات — الصف الثالث الثانوي».
3. أضف سؤالين أو ثلاثة.
4. ولّد اختباراً واحفظه.
5. سجّل ملاحظة ذهنية أو دوّن معرّفات (IDs) لبعض السجلات من استعلام SQL إن أردت اختباراً أدق.

### ب. حساب المعلم ب

1. سجّل خروج المعلم أ.
2. أنشئ حساباً آخر باسم «المعلم ب».
3. أضف مادة وأسئلة مختلفة تماماً.
4. تأكد أن قوائم المواد والأسئلة والاختبارات لا تعرض أي بيانات للمعلم أ.

### ج. العودة إلى المعلم أ

1. سجّل خروج المعلم ب.
2. سجّل دخول المعلم أ.
3. تأكد أن بياناته كما هي، وأن بيانات المعلم ب غير ظاهرة.

### د. اختبارات أمنية إضافية من Console

افتح Console في المتصفح أثناء تسجيل الدخول بحساب **المعلم ب**، ثم نفّذ:

```js
const { createClient } = await import(
  'https://cdn.jsdelivr.net/npm/@supabase/supabase-js@2/+esm'
);

const client = createClient('SUPABASE_URL', 'SUPABASE_ANON_KEY');
const { data: { session } } = await client.auth.getSession();
console.log('مسجل الدخول كـ:', session?.user?.email);

// استبدل UUID_A بـ id سجل حقيقي يخص المعلم أ
const SUBJECT_A = 'UUID_A';
const QUESTION_A = 'UUID_Q_A';
const EXAM_A = 'UUID_EXAM_A';
```

#### 1. محاولة قراءة سجل مستخدم آخر

```js
await client.from('subjects').select('*').eq('id', SUBJECT_A);
// النتيجة: { data: [], error: null }
```

#### 2. محاولة تعديل سجل مستخدم آخر

```js
await client
  .from('questions')
  .update({ question_text: 'محاولة تعديل غير مصرح' })
  .eq('id', QUESTION_A)
  .select();
// النتيجة: data فارغة، ولم يتغير السجل
```

#### 3. محاولة حذف سجل مستخدم آخر

```js
await client.from('questions').delete().eq('id', QUESTION_A).select();
// النتيجة: data فارغة، ولم يُحذف السجل
```

#### 4. محاولة إضافة سؤال داخل مادة مستخدم آخر

```js
await client.from('questions').insert({
  subject_id: SUBJECT_A,
  type: 'short',
  question_text: 'سؤال غير مصرح',
  correct_answer: 'إجابة',
  difficulty: 'easy',
  points: 1
}).select();
// النتيجة: خطأ RLS، لأن subject_id لا يخص المستخدم الحالي
```

#### 5. محاولة إنشاء اختبار مرتبط بمادة مستخدم آخر

```js
await client.from('exams').insert({
  subject_id: SUBJECT_A,
  subject_name_snapshot: 'أي اسم',
  grade_level_snapshot: null,
  title: 'اختبار غير مصرح'
}).select();
// النتيجة: خطأ RLS
```

#### 6. محاولة ربط اختبار بسؤال مستخدم آخر

أنشئ أولاً اختباراً صحيحاً للمعلم ب (أو استخدم `EXAM_B`)، ثم:

```js
await client.from('exam_questions').insert({
  exam_id: 'UUID_EXAM_B',
  question_id: QUESTION_A,
  position: 1,
  snapshot: { question_text: 'x', type: 'short', options: null, correct_answer: 'x', difficulty: 'easy', points: 1, unit: null }
}).select();
// النتيجة: خطأ RLS
```

كذلك جرّب قراءة `exam_questions` الخاصة باختبار المعلم أ:

```js
await client.from('exam_questions').select('*').eq('exam_id', EXAM_A);
// النتيجة: []
```

### النتيجة المتوقعة

- استعلامات القراءة: مصفوفة فارغة `[]`.
- التعديل والحذف: صفر صفوف متأثرة، أو مصفوفة فارغة عند استخدام `.select()`.
- الإدراج المرتبط ببيانات مستخدم آخر: خطأ صريح من RLS.

> لا تعتمد على إخفاء العناصر في الواجهة كحماية؛ الحماية الفعلية تأتي من RLS. حتى لو عدّل المستخدم JavaScript من Console، لن تستطيع قاعدة البيانات إرجاع أو تعديل صفوف لا يملكها.

## 7) اختبار ثبات الاختبارات المحفوظة

هذا الاختبار يثبت أن الاختبارات القديمة تعتمد على `snapshot` ولا تتغير عند تعديل بنك الأسئلة.

1. أنشئ سؤال اختيار من متعدد بخيارات واضحة، وحدد الإجابة الصحيحة.
2. أنشئ اختباراً يحتوي عليه، وفعّل خلط الخيارات، ثم احفظ الاختبار.
3. افتح الاختبار من «الاختبارات المحفوظة» وسجّل:
   - نص السؤال.
   - ترتيب الخيارات كما ظهر.
   - موضع الإجابة الصحيحة.
   - الدرجة.
4. اذهب إلى صفحة الأسئلة وعدّل السؤال الأصلي: غيّر نصه، وخياراته، والإجابة الصحيحة.
5. افتح الاختبار المحفوظ مرة أخرى.
   - يجب أن يبقى النص القديم.
   - يجب أن يبقى ترتيب الخيارات القديم كما هو.
   - يجب أن تبقى الإجابة الصحيحة القديمة.
6. احذف السؤال الأصلي من بنك الأسئلة.
7. افتح الاختبار المحفوظ.
   - يجب أن يبقى السؤال موجوداً داخل الاختبار.
   - يصبح `question_id` في `exam_questions` فارغاً (`NULL`)، لكن `snapshot` يبقى كاملاً.
8. احذف المادة الأصلية بالكامل.
9. افتح الاختبار المحفوظ.
   - يبقى الاختبار موجوداً.
   - تظهر المادة والصف من `subject_name_snapshot` و`grade_level_snapshot`.
   - لا يتأثر الاختبار بحذف المادة.

### تحقق SQL اختياري

من **SQL Editor** في Supabase:

```sql
select id, position, question_id, snapshot
from public.exam_questions
where exam_id = 'UUID_EXAM'
order by position;
```

ستلاحظ أن `snapshot` يحتوي النص والخيارات والإجابة، وأن `question_id` قد يصبح `NULL` بعد حذف السؤال، مع بقاء النسخة التاريخية.

وللتحقق من أن `snapshot` غير قابل للتعديل بعد الحفظ، جرّب:

```sql
update public.exam_questions
set snapshot = '{}'::jsonb
where exam_id = 'UUID_EXAM';
```

يجب أن يفشل التعديل برسالة «لا يمكن تعديل النسخة التاريخية للسؤال بعد حفظ الاختبار».

## 8) ملاحظة أمنية مهمة

- `SUPABASE_ANON_KEY` **ليس مفتاحاً سرياً**. هو مفتاح عام مصمم ليكون ظاهراً في تطبيقات الواجهة، والحماية الحقيقية تأتي من:
  - Supabase Auth.
  - Row Level Security.
  - سياسات قاعدة البيانات والتحقق من العلاقات.
- **لا تضع `service_role key` في الواجهة أو في المستودع أبداً.** هذا المفتاح يتجاوز RLS بالكامل.
- المشروع لا يرسل `user_id` من الواجهة عند الإدراج، ويعتمد على `default auth.uid()`، مع التحقق الإضافي في سياسات RLS.
- جميع بيانات المستخدم المعروضة في الواجهة تُضاف باستخدام `textContent` و`createElement`، وليس عبر `innerHTML`.
- لا تستخدم العميل بـ `service_role` حتى في الاختبار المحلي مع نشر الموقع.

## 9) استكشاف أخطاء شائعة

| المشكلة | السبب المحتمل | الحل |
|---|---|---|
| تظهر رسالة «لم يتم إعداد Supabase» | قيم `js/config.js` ما زالت placeholders | ضع Project URL وanon key |
| تسجيل الدخول يعمل لكن البيانات لا تظهر | لم يُشغَّل `schema.sql` أو فشل جزء منه | أعد تشغيل الملف كاملاً من SQL Editor |
| خطأ RLS عند حفظ اختبار | snapshots المادة لا تطابق المادة الحالية | أعد تحميل الصفحة ثم أعد التوليد |
| رابط تأكيد البريد يعيد خطأ | الرابط غير موجود في Redirect URLs | أضف رابط GitHub Pages وlocalhost |
| الصفحات المحمية تفتح فارغة | لا توجد جلسة أو انتهت | سجّل الدخول من `index.html` |
| الطباعة تُظهر القائمة | الطباعة من صفحة القائمة وليس من داخل اختبار | افتح الاختبار أولاً ثم اطبع |
